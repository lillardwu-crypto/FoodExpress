# 3. Repository 层

今天创建了 Repository 层。

Repository 负责和数据库交互。

例如：

```java
public interface RestaurantRepository extends JpaRepository<Restaurant, Long> {
}
```

这里的意思是：

```text
RestaurantRepository 管理 Restaurant 这个 Entity
Long 表示主键 id 的类型
```

通过继承 `JpaRepository`，Spring Data JPA 自动提供：

```java
save()
findById()
findAll()
deleteById()
existsById()
count()
```

因此我们不用手写基础 SQL。

# 5. RestaurantController 解释

文件位置：

```text
src/main/java/com/foodexpress/controller/RestaurantController.java
```

代码核心：

```java
@RestController
@RequestMapping("/api/restaurants")
@RequiredArgsConstructor
public class RestaurantController {

    private final RestaurantService restaurantService;

    @PostMapping("/sample")
    public Restaurant createSampleRestaurant() {
        return restaurantService.createSampleRestaurant();
    }

    @GetMapping
    public List<Restaurant> getAllRestaurants() {
        return restaurantService.getAllRestaurants();
    }
}
```

---

## 5.1 @RestController

```java
@RestController
```

表示这个类是一个 REST API Controller。

它的作用是：

```text
接收 HTTP 请求
返回 JSON 数据
```

例如浏览器或前端请求：

```http
GET /api/restaurants
```

Spring Boot 会找到对应的 Controller 方法，并返回 JSON。

---

## 5.2 @RequestMapping

```java
@RequestMapping("/api/restaurants")
```

表示这个 Controller 下面所有接口都以：

```text
/api/restaurants
```

开头。

所以：

```java
@GetMapping
```

实际接口是：

```http
GET /api/restaurants
```

而：

```java
@PostMapping("/sample")
```

实际接口是：

```http
POST /api/restaurants/sample
```

---

## 5.3 private final RestaurantService restaurantService

```java
private final RestaurantService restaurantService;
```

Controller 不直接访问数据库。

它把任务交给 Service。

也就是说：

```text
Controller 不负责业务逻辑
Controller 只负责接收请求和返回响应
```

真正逻辑放在：

```text
RestaurantService
```

里面。

# 6. RestaurantService 解释

文件位置：

```text
src/main/java/com/foodexpress/service/RestaurantService.java
```

代码核心：

```java
@Service
@RequiredArgsConstructor
public class RestaurantService {

    private final RestaurantRepository restaurantRepository;

    public Restaurant createSampleRestaurant() {

        List<Restaurant> restaurants =
                restaurantRepository.findAll();

        if (!restaurants.isEmpty()) {
            return restaurants.get(0);
        }

        Restaurant restaurant = Restaurant.builder()
                .name("Boston Burger")
                .address("123 Main St, Boston, MA")
                .phone("617-123-4567")
                .status(RestaurantStatus.OPEN)
                .latitude(new BigDecimal("42.3505000"))
                .longitude(new BigDecimal("-71.1054000"))
                .createdAt(LocalDateTime.now())
                .updatedAt(LocalDateTime.now())
                .build();

        return restaurantRepository.save(restaurant);
    }

    public List<Restaurant> getAllRestaurants() {
        return restaurantRepository.findAll();
    }
}
```

---

## 6.1 @Service

```java
@Service
```

表示这是业务逻辑层。

Service 负责处理业务逻辑，例如：

```text
创建餐厅
查询餐厅
计算订单总价
创建订单
更新订单状态
```

Controller 不应该直接写这些逻辑。

---

## 6.2 RestaurantRepository

```java
private final RestaurantRepository restaurantRepository;
```

Service 通过 Repository 操作数据库。

也就是：

```text
Service 不直接写 SQL
Service 调用 Repository
Repository 调用 JPA
JPA 操作 MySQL
```

---

## 6.3 createSampleRestaurant()

```java
public Restaurant createSampleRestaurant()
```

这个方法用于创建测试数据。

它先查询当前数据库里有没有餐厅：

```java
List<Restaurant> restaurants =
        restaurantRepository.findAll();

if (!restaurants.isEmpty()) {
    return restaurants.get(0);
}
```

这样做的原因是：

```text
避免每次调用 /sample 都重复插入 Boston Burger
```

如果数据库已经有餐厅，就直接返回第一条。

如果没有餐厅，才创建新的 Boston Burger。

---

## 6.4 Restaurant.builder()

```java
Restaurant restaurant = Restaurant.builder()
        .name("Boston Burger")
        .address("123 Main St, Boston, MA")
        .phone("617-123-4567")
        .status(RestaurantStatus.OPEN)
        .latitude(new BigDecimal("42.3505000"))
        .longitude(new BigDecimal("-71.1054000"))
        .createdAt(LocalDateTime.now())
        .updatedAt(LocalDateTime.now())
        .build();
```

这是 Lombok 的 Builder Pattern。

它的作用是更清晰地创建对象。

等价于：

```java
Restaurant restaurant = new Restaurant();
restaurant.setName("Boston Burger");
restaurant.setAddress("123 Main St, Boston, MA");
restaurant.setPhone("617-123-4567");
```

但 Builder 写法更适合字段较多的对象。

它背后大致等价于 SQL：

## 8.2 Lombok 没有生成 builder / constructor

错误表现：

```text
Restaurant.builder() 找不到
restaurantService 未在默认构造器中初始化
```

原因：

```text
Lombok annotation processor 没有正确配置
```

解决方案：

在 `pom.xml` 中添加：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.14.1</version>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>1.18.46</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

然后运行：

```bash
mvn clean compile
```

最终成功。

# 9. 今天学到的软件工程思想

## 9.1 为什么要分 Controller / Service / Repository？

如果 Controller 直接调用 Repository，项目虽然能跑，但代码会越来越乱。

正确分层：

```text
Controller：处理 HTTP 请求
Service：处理业务逻辑
Repository：处理数据库读写
Entity：映射数据库表
```

这样做的好处：

```text
代码职责清晰
后期容易维护
方便测试
方便扩展功能
符合企业项目结构
```

---

## 9.2 当前项目已经不是简单 CRUD

目前 FoodExpress 已经具备：

```text
Spring Boot 后端
MySQL 数据库
JPA Entity 映射
Repository 数据访问层
Service 业务层
Controller API 层
```

这已经是一个标准企业后端项目的基础结构。
