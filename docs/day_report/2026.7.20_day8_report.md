# Day 8 - JWT Integration for Order Module

**Date:** 2026-07-20

---

# Objectives

Today's objective was to integrate JWT authentication into the Order module so that all order-related APIs identify users through the authenticated JWT instead of relying on a user ID provided by the frontend.

This change improves security and aligns the Order module with enterprise backend authentication practices.

---

# Completed Tasks

## 1. Integrated JWT Authentication into OrderController

Updated all order-related endpoints to retrieve the current authenticated user from Spring Security.

Modified APIs:

- Checkout Order
- Get Current User Orders
- Get Order Details

Instead of receiving a `userId` from the request, the controller now uses:

```java
String email = authentication.getName();
```

The authenticated user's email is then passed to the service layer.

---

## 2. Refactored OrderService

Refactored service methods from:

```java
checkout(Long userId)

getUserOrders(Long userId)

getOrder(Long orderId)
```

to:

```java
checkout(String email)

getUserOrders(String email)

getOrder(Long orderId, String email)
```

Added `UserRepository` as a dependency and implemented a helper method:

```java
private User getUserByEmail(String email)
```

The service now retrieves the current user through the authenticated email before executing any business logic.

---

## 3. Added Order Ownership Validation

Implemented authorization logic when retrieving order details.

Only the owner of an order is allowed to access it.

If the order does not belong to the authenticated user, the service returns:

```text
Order not found with id: {orderId}
```

This prevents users from accessing another user's order simply by changing the URL.

---

## 4. Updated Unit Test

Updated `OrderServiceTest` after introducing the new `UserRepository` dependency.

The project compiles successfully after all modifications.

# Security Improvement

## Before

```text
Frontend
      │
      ▼
  userId
      │
      ▼
OrderController
      │
      ▼
OrderService
```

The backend trusted the `userId` sent by the client.

---

## After

```text
JWT
 │
 ▼
Authentication
 │
 ▼
email
 │
 ▼
UserRepository
 │
 ▼
OrderService
```

The backend now derives user identity entirely from the authenticated JWT.

This eliminates the security risk of clients forging another user's `userId`.

# Lessons Learned

- Spring Security provides the authenticated user's identity through the `Authentication` object.
- Business services should never trust user IDs supplied by the frontend.
- User information should always be derived from the authenticated JWT.
- Authorization (resource ownership) should be validated in the service layer rather than the controller.
