# ✅ Completed Tasks

## 1. Bean Validation for Checkout

Introduced Bean Validation to validate request parameters before entering the business layer.

### CheckoutRequest

```java
@NotNull(message = "userId is required")
private Long userId;
```

### Controller

```java
@Valid
@RequestBody
```

### Result

- Invalid requests are rejected immediately.
- Prevents unnecessary Service execution.
- Returns HTTP 400 instead of HTTP 500.

## 4. Implemented Order State Machine

Added:

```java
updateOrderStatus(...)
```

and

```java
canTransition(...)
```

Current workflow:

```text
PENDING
    ↓
ACCEPTED
    ↓
PREPARING
    ↓
READY_FOR_PICKUP
    ↓
OUT_FOR_DELIVERY
    ↓
DELIVERED
```

Cancellation rules:

```text
PENDING
    ↓
CANCELLED

ACCEPTED
    ↓
CANCELLED
```

Illegal transitions are rejected automatically.

Example:

```text
DELIVERED
      ↓
PREPARING

❌ Rejected
```

# 📚 Key Learnings

Today's biggest takeaway was understanding that an order lifecycle should never allow arbitrary status updates.

Instead, every order must follow a predefined workflow.

```text
PENDING
    ↓
ACCEPTED
    ↓
PREPARING
    ↓
READY_FOR_PICKUP
    ↓
OUT_FOR_DELIVERY
    ↓
DELIVERED
```

This state machine design prevents invalid business operations and provides a solid foundation for future modules such as:

- Payment
- Delivery
- Notification
- Refund

In addition, introducing JUnit + Mockito enables automated verification of business logic instead of relying solely on manual API testing.
