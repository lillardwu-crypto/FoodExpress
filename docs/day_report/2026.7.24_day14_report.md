# Day 13 Report – Merchant Backend

**Date:** 2026-07-24

---

# Objective

Complete the first phase of the Merchant Backend by allowing restaurant owners to securely manage their orders using JWT authentication and role-based authorization.

---

# Features Implemented

## 1. Merchant Order Query

Implemented the endpoint:

```http
GET /api/merchant/orders
```

Features:

- Retrieve all orders belonging to the authenticated merchant.
- Determine restaurant ownership using the merchant's JWT identity.
- Return orders sorted by creation time in descending order.

---

## 2. Merchant Order Status Update

Implemented the endpoint:

```http
PATCH /api/merchant/orders/{orderId}/status
```

Supported merchant workflow:

```text
PENDING
    ↓
ACCEPTED
    ↓
PREPARING
    ↓
READY_FOR_PICKUP
```

Business validations:

- Merchant authentication is required.
- Merchant can only update orders belonging to their own restaurant.
- Duplicate status updates are rejected.
- Invalid status transitions are rejected.

---

## 3. Repository Enhancements

Added custom repository methods to simplify merchant-related queries.

### RestaurantRepository

```java
Optional<Restaurant> findByOwner_Id(Long ownerId);
```

### OrderRepository

```java
List<Order> findByRestaurant_IdOrderByCreatedAtDesc(Long restaurantId);
```

These methods allow merchants to retrieve only the orders belonging to their own restaurant.

# Testing

## Successful Scenarios

- Merchant login using JWT.
- Retrieve merchant orders.
- Update order status:
  - PENDING → ACCEPTED
  - ACCEPTED → PREPARING
  - PREPARING → READY_FOR_PICKUP

## Exception Scenarios

- Duplicate status update returns **409 Conflict**.
- Invalid status transition returns **409 Conflict**.
- Updating a non-existent order returns **404 Not Found**.
- Attempting to update another merchant's order returns **404 Not Found**, preventing unauthorized access and avoiding information leakage.

---

# Business Rules

Merchant permissions:

- View only orders belonging to their own restaurant.
- Update only orders belonging to their own restaurant.

Allowed order transitions:

```text
PENDING
    ↓
ACCEPTED
    ↓
PREPARING
    ↓
READY_FOR_PICKUP
```

Any other transition is rejected.
