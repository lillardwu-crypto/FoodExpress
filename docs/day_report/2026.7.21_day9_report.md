Day 9 - JWT Integration for Cart Module & End-to-End Regression Testing

Date: 2026-07-20

Today's Goal

Remove the dependency on userId in the Cart APIs and make the Cart module identify the current user through JWT authentication.

After the refactor, all cart operations should work based on the authenticated user instead of trusting the client to provide a user ID.

Completed Tasks
1. Refactored Cart APIs

Updated the REST API design.

Before:

POST /api/carts/{userId}/items
GET  /api/carts/{userId}

After:

POST /api/carts/items
GET  /api/carts
PUT  /api/carts/items/{cartItemId}
DELETE /api/carts/items/{cartItemId}

The frontend no longer sends a user ID.

2. JWT-based User Identification

Modified the CartController to obtain the current authenticated user from Spring Security.

Instead of:

@PathVariable Long userId

the controller now uses:

Authentication authentication

and retrieves:

authentication.getName()

which contains the authenticated user's email.

3. CartService Refactoring

Changed all CartService methods to use email instead of userId.

Before:

addItemToCart(Long userId,...)

After:

addItemToCart(String email,...)

Added:

private User getUserByEmail(String email)

to retrieve the authenticated user.

4. Ownership Validation

Added ownership validation to protect cart resources.

Before updating or deleting a cart item, the service verifies:

Cart.user.email == Authentication.email

Unauthorized access now throws an exception instead of allowing users to modify another user's cart.

Key Learnings
Using JWT eliminates the need for client-provided user IDs.
Controllers should obtain user identity from Spring Security instead of trusting request parameters.
Business logic should remain inside the Service layer.
Ownership validation is essential for protecting user resources.
After refactoring authentication logic, regression testing is necessary to ensure downstream modules continue working.
