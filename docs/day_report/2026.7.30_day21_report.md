# Today's Goal

Continue improving the Order module by introducing a role-based order state machine and separating responsibilities for Customer, Merchant, and Driver.

---

# Backend Progress

## 1. Refactored Customer Order API

Removed the generic order status update endpoint and replaced it with a dedicated customer cancellation API.

### Previous API

```http
PATCH /api/orders/{orderId}/status
```

### New API

```http
PATCH /api/orders/{orderId}/cancel
```

This prevents customers from modifying arbitrary order statuses.

---

## 2. Implemented Customer Order Cancellation

Added a new service method:

```java
cancelCustomerOrder(...)
```

Supported state transitions:

```text
PENDING
    ↓
CANCELLED

ACCEPTED
    ↓
CANCELLED
```

Customers are no longer allowed to cancel an order once food preparation has started.

Blocked statuses:

- PREPARING
- READY_FOR_PICKUP
- OUT_FOR_DELIVERY
- DELIVERED
- CANCELLED

---

## 3. Refactored Order Status Logic

Removed the old generic implementation:

```java
updateOrderStatus(...)
```

Also removed:

```java
canTransition(...)
```

The order workflow is now separated by business role instead of allowing one generic state transition method.

---

## 4. Merchant Workflow Preserved

Merchant state transitions remain:

```text
PENDING
      ↓
ACCEPTED
      ↓
PREPARING
      ↓
READY_FOR_PICKUP
```

Merchant logic already exists in `OrderService` and will be exposed through a dedicated controller in the next development phase.

---

## 5. Driver Workflow Preserved

Driver delivery workflow remains:

```text
READY_FOR_PICKUP
        ↓
OUT_FOR_DELIVERY
        ↓
DELIVERED
```

Existing driver service methods remain unchanged.

---

## 6. Refactored OrderController

Customer-facing APIs are now:

```http
POST   /api/orders
GET    /api/orders
GET    /api/orders/{id}
PATCH  /api/orders/{id}/cancel
```

Customers are now limited to viewing orders and cancelling eligible orders only.

---

## 7. Updated Unit Tests

Refactored `OrderServiceTest` to match the new cancellation workflow.

Added test cases for:

- Cancel ACCEPTED order
- Reject PREPARING cancellation

- Order not found
