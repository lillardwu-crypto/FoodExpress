# JPA 学习

## @Entity

表示：

```text
Java类
↓
数据库实体
```

---

## @Table

表示：

```text
数据库表名
```

例如：

```java
@Table(name = "order_items")
```

对应：

```sql
order_items
```

---

## @ManyToOne

表示：

```text
多对一关系
```

例如：

```text
多个MenuItem
属于
一个Restaurant
```

---

## @OneToMany

表示：

```text
一对多关系
```

例如：

```text
一个Restaurant
拥有多个MenuItem
```

---

## @JoinColumn

指定：

```text
数据库外键列
```

例如：

```java
@JoinColumn(name = "restaurant_id")
```

对应：

```sql
restaurant_id
```

---

## mappedBy

理解：

```text
不是表名
不是列名
而是对方实体中的字段名
```

例如：

```java
@OneToMany(mappedBy = "restaurant")
```

对应：

```java
private Restaurant restaurant;
```

---

# Owning Side 与 Inverse Side

学习：

## Owning Side

拥有：

```java
@JoinColumn(...)
```

的一侧。

负责维护数据库关系。

例如：

```java
MenuItem
```

中的：

```java
private Restaurant restaurant;
```

---

## Inverse Side

拥有：

```java
mappedBy
```

的一侧。

用于反向访问。

例如：

```java
Restaurant.menuItems
```

---

# 双向关系设计原则

重要结论：

```text
数据库关系
≠
JPA关系
```

---

更准确地说：

```text
JPA关系
≈
业务访问路径
```

---

因此：

## 保留双向关系

```text
Restaurant -> MenuItems
Cart -> CartItems
Order -> OrderItems
```

因为业务高频访问。

---

## 暂不添加双向关系

```text
User -> Carts
Restaurant -> Carts
User -> Orders
```

因为更适合 Repository 查询。

---

# OrderItem 设计

重点学习：

```text
CartItem
≠
OrderItem
```

---

CartItem：

实时数据

适合关联：

```java
MenuItem
```

---

OrderItem：

历史快照

保存：

```java
menuItemId
menuItemName
price
quantity
```

避免菜单修改影响历史订单。
